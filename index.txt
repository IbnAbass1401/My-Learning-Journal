# Blog 2 — My First Steps With HTML

After deciding to seriously learn web development, HTML was where everything started.

Before learning HTML, I could use websites normally, but I never really thought about what was happening behind the screen.

HTML changed that.

I started learning about elements, attributes, headings, paragraphs, links, images, lists, buttons, forms and the basic structure of a webpage.

At first, I was mostly focused on remembering the different tags and understanding where everything was supposed to go.

Eventually, I started understanding that HTML wasn't really about making a website look beautiful.

HTML provides the **structure and meaning** of the page.

I also started learning about semantic HTML and why using the correct element matters. Instead of using a generic element for everything, I began understanding elements like `<header>`, `<nav>`, `<main>`, `<section>`, `<article>` and `<footer>`.

Accessibility also started making more sense to me during this stage.

I realized that a website isn't only being viewed by someone sitting in front of a laptop. Different people interact with websites in different ways, so the structure of the page actually matters.

One of the things that helped me most was building things rather than simply reading about them.

I built simple pages and eventually worked on projects like a YouTube clone while learning HTML and CSS.

It wasn't perfect, but it gave me something important: I was no longer just learning what HTML tags were.

I was learning how to use them to build something.

And that became the pattern for the rest of my journey.

# Blog 3 — When CSS Started Making Sense

HTML gave my websites structure, but CSS was when they started looking like actual websites.

This was probably one of the stages where I learnt the most about how webpages are laid out.

I started with the basics: selectors, classes, colours, fonts, margins, padding and the box model.

Then I started getting deeper into layouts.

Flexbox was one of the concepts that changed the way I thought about positioning elements. Instead of trying to force elements into specific positions, I could control how elements were arranged inside a container.

I also learnt about positioning, spacing, `gap`, different units, typography, pseudo-classes, transitions, animations and CSS variables.

DevTools became another important part of learning CSS.

Instead of constantly changing my code and refreshing the page without knowing what was happening, I could inspect an element, see its styles and experiment with different values directly in the browser.

I also started learning more about accessibility, including colour contrast and making sure text could actually be read against its background.

One thing I gradually realized was that CSS isn't really about memorising hundreds of properties.

It's more about understanding how the properties affect the relationship between elements.

For example, learning `display: flex` wasn't just learning another CSS property.

It was learning a completely different way of thinking about layouts.

The more I practiced, the more comfortable I became.

But I also discovered that being comfortable with CSS on my own screen didn't necessarily mean I knew how to build a website that worked everywhere.

That would become my next big challenge.

When I moved from HTML and CSS into JavaScript, things became noticeably harder.

HTML and CSS felt more visual to me. I could change something and immediately see what happened.

JavaScript required me to actually understand logic.

I started learning about variables, functions, conditionals, loops, arrays, events and the DOM.

At first, some of these concepts felt confusing.

I remember having situations where my code technically looked right to me, but it wasn't doing what I expected.

One of the biggest things that helped was building projects.

At one point, instead of getting the value I wanted, I ended up seeing things like `[object HTMLInputElement]` and `NaN`.

It turned out I was trying to perform calculations using the input element itself instead of the value inside it.

That kind of mistake taught me something that tutorials can't really teach on their own:

**the error is part of the learning process.**

I started becoming more comfortable with things like `.value`, `.textContent`, event listeners, `querySelector`, `querySelectorAll` and manipulating elements through JavaScript.

JavaScript was still challenging, but I started noticing something.

The more projects I built, the less mysterious the concepts became.

I wasn't suddenly an expert, but things that initially looked completely foreign started becoming familiar.

And that gave me the confidence to keep going.

# Blog 5 — I Finally Started Understanding Responsive Design

For a while, I mostly thought about whether my website looked good on the screen I was using.

Then I started learning responsive design.

That changed the way I looked at websites.

A website isn't really finished just because it looks good on a laptop.

What happens when someone opens it on a 320px phone?

What happens when the screen becomes wider?

What happens when the navigation no longer fits?

What happens when a heading wraps onto three lines?

These were the kinds of questions I started thinking about.

I began learning about mobile-first design, media queries, breakpoints and responsive layouts.

CSS Grid became especially important.

I learnt about `grid-template-columns`, `repeat()`, `gap`, `span`, `grid-column`, `grid-row` and `grid-template-areas`.

I personally started preferring `grid-column` and `grid-row` in many situations because I found them more straightforward to understand.

One of the biggest things I learnt was that responsive design isn't simply about making everything smaller.

It's about allowing the layout to **adapt**.

An element might be beside another element on a desktop but move underneath it on a phone.

A three-column layout might become two columns and eventually one column.

The typography and spacing might change.

The navigation might need a completely different arrangement.

That was when responsive design started becoming more than just a CSS topic to me.

It became a way of thinking about how people actually use websites.

# Blog 6 — Learning to Test What I Build

Learning responsive design was one thing.

Actually applying it was another.

I started testing my websites at different screen widths instead of only looking at them on my laptop.

I began checking sizes such as 320px, 375px, 430px, 768px, 1024px and larger desktop widths.

That helped me notice problems I wouldn't have seen otherwise.

Sometimes text would wrap differently.

Sometimes an image wouldn't behave the way I expected.

Sometimes elements would become too close together.

Sometimes a navigation would fit perfectly on my laptop but become cramped on a phone.

This taught me why mobile-first development is useful.

Instead of starting with a large desktop layout and trying to squeeze everything into a smaller screen afterwards, I could start with the smallest practical layout and progressively improve it as more space became available.

I also learnt that there isn't necessarily a magic breakpoint for every device.

The important question isn't:

*"What breakpoint does this particular phone use?"*

It's:

*"At what point does my layout need to change?"*

That is a much more useful way of thinking about responsive design.

I'm now applying this knowledge while building my own Learning Journal.

So instead of just learning responsive design as another topic, I'm using this project to test whether I actually understand it.
